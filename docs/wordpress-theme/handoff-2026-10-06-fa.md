# آرشیو این گفتگو و ادامهٔ کار روی سیستم دیگر

## ادامهٔ اصلاحات زنده در همین روز

پس از این آرشیو، کارت‌های نوآوری، هشدار و ناوبری گالری بیماران، صفحات
خدمات و راهنماهای سه‌زبانه و breadcrumb تکمیل شدند. آخرین وضعیت و چک‌لیست
تحویل در [گزارش امروز](employer-report-2026-10-06-fa.md) و تصمیم‌های این
گفتگو در [بازطراحی خدمات](clinical-care-redesign-2026-10-06-fa.md) آمده‌اند.
مالک «کلرهگزیدین ۲٪» و استفاده از nobat.ir/9705 برای تمام مراکز را تأیید کرد.
این بخش وضعیت اصلاحات محدود زنده را به‌روز می‌کند؛ موضوع نصب کامل ۳.۵.۱ و
GUIDهای قدیمی که در ادامه شرح داده شده همچنان مستقل است.

تاریخ ثبت: ۲۰۲۶-۱۰-۰۶، منطقهٔ زمانی Europe/Istanbul.

این سند درخواست‌ها، پاسخ‌های مالک، تصمیم‌های اجرایی، تغییرات، آزمون‌ها و نقطهٔ
توقف گفتگوی Patients/Innovation را به‌صورت ساختاریافته ثبت می‌کند. جزئیات
محتوای عمومی و کد در فایل‌های پیوندشده موجود است؛ نام کامل بیماران، پرونده‌های
پزشکی، نشست مرورگر و داده‌های ورود بخشی از این آرشیو Git نیستند.

### ۱. مطالعهٔ ریپو و ساخت بخش بیماران

مالک اجازهٔ استفاده از مرورگرِ واردشده به سایت را برای تست و رفع باگ داد و
خواست README، changelog و مستندات به‌روز و کامیت‌ها پوش شوند.

  افزودن بیمار، دسته‌بندی و برچسب‌ها اضافه شد.
- هر پرونده عنوان، خلاصه، شرح و اقدامات، دسته/برچسب و گالری مرتب‌شدهٔ عکس،
  ویدیو و لینک ویدیو دارد.
- منبع اولیهٔ طبقه‌بندی و رسانه‌ها:
  `My Drive/_projects/dr.ali-moradi/Patients-site-2`.
  پوشه‌های بیماری/اقدام دسته و زیردسته شدند؛ پوشه‌های نام اشخاص پروندهٔ بیمار
  شدند. مالک پذیرفت اپراتور بعداً دسته‌بندی‌های تشخیص‌داده‌شده را اصلاح کند.
- یکی و فقط یکی از گروه‌های **کلینیک** و **بیمارستان** برای هر بیمار الزامی
  شد؛ دسته‌های بیماری علاوه بر این گروه باقی می‌مانند.
- پاسخ صریح مالک برای ورود اولیه: **«بیمارستان؛ اپراتور موارد کلینیک را
  اصلاح کند»**. تعیین محل مراقبت از نام بیماری حدس زده نشد.
- دو گالری پایین Clinical Care از بیماران منتشرشده در این دو گروه خوانده
  می‌شوند؛ مقصدهای موجود View full gallery حفظ شدند.
- آرشیو دسته، بیماران همان دسته و زیرمجموعه‌ها را نشان می‌دهد. جلد دسته از
  اولین تصویر پرونده در مسیر زیرمجموعه، عنوان و لایهٔ رنگی ۶۰٪ استفاده می‌کند.
- درخت بازوبسته‌شوندهٔ دسته‌ها تا سطح بیمار با +/−، صفحه‌بندی و lightbox
  متناسب با تصویر، عنوان، توضیح و لینک پرونده اضافه شد.

مدل، قواعد اجباری و جریان اپراتور در [راهنمای بیماران](patients.md) ثبت است.

### ۲. ورود انبوه رسانه، زبان و سئو

مالک خواست بارگذاری ادامه پیدا کند، رسانه‌های موجود دوباره آپلود نشوند و راه
بهتری برای تعداد زیاد فایل ارائه شود. استفاده از پنل هاست برای بسته‌های ZIP
و ثبت بعدی آن‌ها در Media Library را صریحاً تأیید کرد.

- بسته‌بندی محلی با checksum و staging بیرون از web root پیاده شد؛ ابزار
  واردکننده فایل‌ها را با API وردپرس در Media ثبت و به پرونده‌ها متصل می‌کند.
  انتقال فایل به uploads به‌تنهایی جایگزین ثبت attachment نیست.
- source ID و hash مانع تکرار شدند؛ ۹ رسانهٔ موجود دوباره استفاده شد.
  فایل AppleDouble که ظاهراً تصویر ۳۱۵ام بود، تصویر واقعی نبود و وارد نشد.
- نتیجهٔ نهایی ورود ۳۱۴ رسانه در ۷۱ پرونده است؛ **این ورود کامل شده و نباید
  برای ادامهٔ کار از ابتدا تکرار شود**.
- مالک فعال‌سازی Allow access to file URLs برای افزونهٔ Chrome را تأیید و
  خودش انجام داد. به‌دلیل مشکل اتصال، Chrome را بست و دوباره باز کرد.
  چند توقف انتخابگر فایل نیز با قفل‌شدن مک مرتبط بود و مالک هر بار بازشدن مک
  را اعلام کرد. این‌ها تاریخچهٔ محیط‌اند، نه نشانهٔ ورود ناقص رسانه‌ها.
- صفحه‌بندی و برچسب‌های گالری تابع زبان بازدیدکننده شدند؛ انگلیسی از ارقام
  لاتین استفاده می‌کند. بیمار و رسانه مشترک‌اند و فیلدهای متن EN/FA/AR دارند؛
  ترجمهٔ بالینی خودکار برای پرونده‌های فاقد ترجمه تولید نشد.
- metadata، canonical و لینک زبان‌ها اصلاح شد؛ sitemap دسته‌های بیماران
  فعال و rewrite rules بازسازی شد. پیام نوع محتوای جدید Rank Math پس از
  پیکربندی رسیدگی و بسته شد.
- در نسخهٔ ۳.۴، تصاویر حساس از image sitemap کنار گذاشته شدند؛ این فیلتر با
  کد و آزمون تأیید شد، اما بررسی مستقیم XML همان نوبت در مرورگر مسدود بود.

مالک خواست تب‌های اضافی بسته شوند تا RAM مصرف نشود و نام بیماران مخفف شود.
کار با یک تب موقت ادامه یافت؛ تب‌های متعلق به خود کاربر بسته نشدند.

- از خروجی خصوصی Patients، ۳۶ عنوانِ نام شخص تشخیص داده شد. پنج بدنه و دو
  رکورد گالری همان نام کامل را تکرار می‌کردند. ۳۳ تصویرِ متعلق به بیمار نیز
  filename فارسی داشتند. عنوان‌های پزشکی و پروندهٔ شماره‌دار حفظ شدند.
- نسخهٔ ۳.۵.۰ نام‌ها را به حروف اول، slug را به `case-{id}` و مسیرهای رسانه
  را به `case-media-{id}` تبدیل کرد؛ متن/کپشن متناظر و `_wp_old_slug` اصلاح
  شدند. اصل تصویر، اندازه‌های ثبت‌شده و metadata با هم منتقل شدند.
- خطای مسیرهای symlink در آزمون محلی با مقایسهٔ `realpath()` رفع شد.
- نصب ۳.۵.۰ و اجرای ۶۹ عملیات با صفر خطا تأیید شد. خروجی تازه و صفحات نمونه
  نام مخفف و مسیرهای خنثی را تأیید کردند.
- ممیزی خروجی نشان داد GUID قدیمی هر ۳۶ بیمار و ۳۳ رسانه باقی مانده است؛ دو
  نام کامل قبلی و ۳۲ filename قبلی هنوز در GUID رسانه‌ها دیده می‌شدند.
  بنابراین پاک‌سازی هویت **به‌طور کامل تمام نشده است**.
- نسخهٔ ۳.۵.۱ GUID را از طریق `$wpdb->update()` تغییر می‌دهد و cache پست را
  پاک می‌کند. replay برای پرونده‌های علامت‌خورده فقط GUID را اصلاح می‌کند و
  فایل را دوباره جابه‌جا نمی‌کند. آزمون این شاخهٔ تکرارپذیر نیز موفق است.
- انتخاب ZIP اصلاحیه در صفحهٔ آپلود پوسته توسط بررسی خودکار مرورگر با پیام
  «اجازهٔ این درخواست رد شده است» مسدود شد. مالک پس از توضیح، **همین آپلود و
  بازاجرای ۶۹ عملیات را دوباره صریحاً تأیید کرد**؛ ابزار باز هم همان رد را داد.
  هیچ مسیر دیگری برای دورزدن آن استفاده نشد. اجازهٔ متنی مالک موجود است،
  ولی موفقیت ابزار یا نصب ۳.۵.۱ را نباید از آن نتیجه گرفت.

### ۸. مستندات، کامیت‌ها و انتقال به سیستم دیگر

مالک چند بار خواست تمام کارها مستند، کامیت‌های محلی پوش و شاخه‌ها ادغام شوند.
همهٔ تغییرات تا `6fc223d` در دو شاخهٔ GitHub همگام شدند؛ تگ‌های ۳.۵.۰ و ۳.۵.۱
نیز پوش شدند. ادغام‌ها fast-forward بودند و force push انجام نشد. درخواست
نهایی این نوبت، ثبت تمام زمینهٔ همین گفتگو برای ادامهٔ ادیت روی سیستم دیگر است؛
این راهنما پاسخ به همان درخواست است.

در ممیزی همین انتقال مشخص شد `tests/wordpress-patient-privacy.php` در کامیت‌های
قبلی سه نام واقعی را به‌عنوان نمونهٔ آزمون داشت. در آخرین نسخهٔ شاخه، همهٔ آن
نمونه‌ها و slugهای متناظر با عبارت‌های آشکارا آزمایشی جایگزین و آزمون privacy
دوباره اجرا شد. تطبیق سایر فایل‌های متنی با عنوان‌های export فقط اشتراک یک
نام خانوادگی با اعضای تیم را نشان داد؛ مشخصات عمومی اعضای تیم تغییر نکرد.

این اصلاح **محتوای کامیت‌های قدیمی و تگ‌ها را پاک نمی‌کند**. نام‌های fixture
از تاریخچهٔ آغازشده در `2114148` و تگ‌های ۳.۵.۰/۳.۵.۱ قابل بازیابی‌اند؛ رسیدگی
به آن یک کار باز برای بازبینی حریم خصوصی تاریخچه است. بازنویسی تاریخچه و force
push انجام نشده و باید با مالک و سایر checkoutها هماهنگ شود. فایل تست خارج
از پوشهٔ پوسته است، بنابراین در ZIPهای نصب پوسته قرار ندارد و checksum بستهٔ
۳.۵.۱ با این اصلاح عوض نمی‌شود. ادعای قدیمی «هیچ نامی در Git ثبت نشده» با این
یافته تصحیح می‌شود؛ export خام و تصاویر بیماران به Git اضافه نشده‌اند.

## شروع روی سیستم جدید

برای clone تازه، نام remote را مطابق مستندات `upstream` انتخاب کنید:

```sh
git clone --origin upstream https://github.com/moghadam-pro/dr.ali.moradi-webiste.git DrAliMoradi
cd DrAliMoradi
git switch main
git fetch upstream --tags
git pull --ff-only upstream main
```

اگر checkout از قبل وجود دارد، ابتدا `git status` و `git remote -v` را بخوانید؛
تغییرات محلی را حفظ و remote ریپوی اصلی را استفاده کنید. نام `origin` در یک
clone تازه ممکن است کاملاً معتبر باشد؛ URL ملاک است. سپس این سند، گزارش
پیشرفت و [راهنمای نسخه‌بندی](versioning.md) را بخوانید.

برای ادامهٔ کدنویسی Node/npm مطابق `package.json` و lockfile و PHP سازگار با
پوسته لازم است. در محیط تازه `npm ci` و سپس `npm test` اجرا می‌شود. آخرین اجرای
کامل `npm test` برای کد ۳.۵.۱ موفق بود: build، پنج بررسی HTML رندرشده و آزمون‌های
WordPress نسخه، بیماران، privacy، SEO، نوآوری، نویسه‌های عربی و content updates.
تغییرات این راهنما فقط مستندات‌اند و نسخهٔ پوسته را عوض نمی‌کنند.

## مراحل دقیق کار باز

1. نسخهٔ واقعاً فعال سایت و هر تغییر احتمالی پوسته پس از این گفتگو را بررسی
   کنید. اگر Production تغییر تازه دارد، قبل از جایگزینی با Git تطبیق دهید.
2. در محیطی که ابزار مرورگر اجازهٔ عادی بارگذاری می‌دهد، ZIP دقیق تگ ۳.۵.۱ را
   از Appearance → Themes → Upload نصب و جایگزینی ۳.۵.۰ → ۳.۵.۱ را تأیید کنید.
   رد ابزار قبلی را با مسیر غیرمجاز دور نزنید؛ این راهنما مجوز ابزار را تغییر
   نمی‌دهد. در این نوبت انتقال مستندات، نصب دوباره امتحان نشده است.
3. در Tools → درون‌ریزی بیماران (`tools.php?page=dam-patient-import`) manifest
   خصوصی قبلی را دوباره اجرا کنید. انتظار: **۶۹ completed و صفر failed**.
   این بار عملیات برای موارد علامت‌خورده به اصلاح GUID محدود می‌شود.
4. یک خروجی تازه از Tools → Export → Patients بگیرید و بررسی کنید: ۷۱ بیمار،
   ۳۱۴ attachment، ۳۶ GUID بیمار با `urn:dralimoradi:patient:{id}` و ۳۳ GUID
   رسانه با URL فعلی `case-media-{id}`؛ نام/مسیر قبلی در فیلدهای عمومی، GUID و
   metadata موارد هدف نمانده باشد. اصل و اندازه‌های عکس بارگذاری شوند.
5. چند پرونده، گالری، لینک زبان و هشدار رسانه را بررسی کنید؛ فقط با نام مخفف
   گزارش دهید. فایل‌های خصوصی در Git قرار نگیرند.
6. وضعیت نصب‌شده را در README، راهنمای WordPress و progress log به ۳.۵.۱
   تغییر دهید، checksum و نتیجهٔ واقعی را ثبت و کامیت/پوش کنید. شاخه‌های
   `main` و `codex/patients-gallery` همگام بمانند و تب‌های موقت بسته شوند.

بازسازی بستهٔ نصب بدون وابستگی به فایل موقت سیستم قبلی:

```sh
TZ=Europe/Istanbul git archive --format=zip --prefix=dr-ali-moradi/ --mtime='2026-10-06T10:47:19Z' theme-v3.5.1:wordpress-theme/dr-ali-moradi > /tmp/dr-ali-moradi-3.5.1.zip
shasum -a 256 /tmp/dr-ali-moradi-3.5.1.zip
```

نسخهٔ Git باید گزینهٔ `--mtime` را پشتیبانی کند. زمان و timezone بالا عمداً
ثابت‌اند: archive از tree بدون این تنظیمات زمان جاری را ذخیره می‌کند و با
وجود محتوای یکسان، checksum متفاوت می‌شود. دستور بالا در همین سیستم آزمایش
و برابری checksum آن با بستهٔ اصلی تأیید شد.

SHA-256 بستهٔ ۳.۵.۱:
`67313c5e48c28ccc7ab7aaf1c030d9b4b239a75ebb9256593c6613786db0c045`.
SHA-256 بستهٔ نصب‌شدهٔ ۳.۵.۰:
`40f868d3635ffc051de9198a1372d2a7e576ebb784ec23f8782ff3cebff9af7e`.

## فایل‌های محلی که Git منتقل نمی‌کند

در زمان ثبت این راهنما، موارد زیر روی سیستم قبلی موجود بودند:

| مسیر روی سیستم قبلی | کاربرد |
|---|---|
| `/tmp/dam-patient-privacy-2026-10-06.json` | ۶۹ عملیات با ID و hash؛ بدون نام و مسیر منبع، ولی manifest خصوصی و خارج از Git |
| `/tmp/dr-ali-moradi-3.5.1.zip` | بستهٔ قابل بازسازی از تگ؛ ۳.۵.۱ نصب نشده است |
| `~/Downloads/dralimoradihandsurgeonharvarduniversity.WordPress.2026-10-06.xml` | خروجی خصوصی پیش از مخفف‌سازی؛ حاوی دادهٔ شناسایی‌کننده |
| `~/Downloads/dralimoradihandsurgeonharvarduniversity.WordPress.2026-10-06 (1).xml` | خروجی خصوصی بعد از ۳.۵.۰، برای ممیزی و GUIDهای باقی‌مانده |

پوشهٔ `/tmp` پایدار نیست. برای ادامه می‌توان manifest را به‌صورت خصوصی منتقل
کرد یا از خروجی تازهٔ Patients ساخت؛ نیازی به انتقال عکس‌های قبلاً واردشده نیست.
exportها، عکس‌ها، ZIPهای رسانه، کوکی‌ها، nonceها و اطلاعات ورود را commit نکنید.

اگر manifest قبلی در دسترس نبود، در خروجی تازه فقط رکوردهای دارای نشانگر
`_dam_patient_privacy_version=1` یا `_dam_patient_privacy_media_version=1` را
انتخاب کنید. نمونهٔ زیر manifest را خارج از ریپو می‌سازد، هیچ دادهٔ هویتی را
چاپ نمی‌کند و برای وضعیت ثبت‌شده شمارش ۳۶/۳۳ را الزام می‌کند. اگر شمارش تغییر
کرد، ابتدا دلیل آن را بررسی کنید؛ شرط را بدون ممیزی حذف نکنید.

```python
import hashlib
import json
from collections import Counter
from pathlib import Path
import xml.etree.ElementTree as ET

source = Path('/absolute/private/path/patients-export.xml')
output = Path('/tmp/dam-patient-guid-replay.json')
wp = '{http://wordpress.org/export/1.2/}'
operations = []
for item in ET.parse(source).getroot().findall('.//item'):
    meta = {
        row.findtext(wp + 'meta_key'): row.findtext(wp + 'meta_value', '')
        for row in item.findall(wp + 'postmeta')
    }
    post_type = item.findtext(wp + 'post_type')
    post_id = int(item.findtext(wp + 'post_id'))
    if post_type == 'patient' and meta.get('_dam_patient_privacy_version') == '1':
        kind = 'anonymize_patient'
        hash_key = 'expected_title_sha256'
        value = item.findtext('title', '').strip()
    elif post_type == 'attachment' and meta.get('_dam_patient_privacy_media_version') == '1':
        kind = 'anonymize_media'
        hash_key = 'expected_path_sha256'
        value = meta['_wp_attached_file']
    else:
        continue
    operations.append({
        'kind': kind, 'id': post_id, 'key': f'guid-replay-{kind}-{post_id}',
        hash_key: hashlib.sha256(value.encode('utf-8')).hexdigest(),
    })
assert Counter(op['kind'] for op in operations) == {
    'anonymize_patient': 36, 'anonymize_media': 33,
}
output.write_text(json.dumps({'operations': operations}, indent=2), encoding='utf-8')
output.chmod(0o600)
print(f'Prepared {len(operations)} replay operations.')
```

نشانگرهای ثبت‌شده باعث می‌شوند ۳.۵.۱ پیش از تغییر مجدد عنوان/فایل به شاخهٔ
اصلاح GUID برود. این دستورالعمل برای بازاجرای همین مهاجرت است؛ برای بیمار
جدید باید عنوان و مسیر قبل از انتشار جداگانه بررسی شوند.
